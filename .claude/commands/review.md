`data/` 폴더의 회의록 PDF를 **`patterns.md` §9 회의록 수정 상시 체크리스트로 전수 검토**하여, **변경 근거표(단일 산출물)** 를 만들고, **확정된 수정사항을 누적 대장에 축적**하라. (수정본·DOCX는 만들지 않는다 — 보고서 반영은 작성자가 직접 하며, 우리는 "무엇을 왜 고칠지"의 표만 제공한다.)

> 트리거: 사용자가 PDF를 `data/`에 넣고 `/review`를 입력하면 실행된다. (폴더 감시 훅은 없으므로 파일 드롭만으로 자동 실행되지는 않음 — `/review` 입력이 트리거다.) 파일명을 인자로 주면 그 파일을, 생략하면 아래 후보 중 가장 최근 PDF를 대상으로 한다.

## 대상 파일 자동 감지
- 지정 파일(선택): $ARGUMENTS
- data/ 최신 PDF 후보 (수정시각 내림차순):
!`ls -t "data"/*.pdf 2>/dev/null | head -8`
- 이미 검토됨(_ext.txt 존재) 여부 참고:
!`ls -t "data"/*_ext.txt 2>/dev/null | head -8`

→ `$ARGUMENTS`가 있으면 그 파일, 없으면 위 목록 맨 위 PDF(단, `*_rev.pdf`·`*_ext.txt`는 제외)를 대상으로 삼는다. 애매하면 대상 파일명을 한 줄로 확인받고 진행.

## 절차

### 0. 입력 자산 로드 (누적 기준 총동원)
1. 대상 PDF를 pdfplumber로 추출 → `data/<파일명>_ext.txt` 생성. **콘솔 인코딩 오류 방지: 반드시 파일로 저장 후 Read로 읽는다** (cp949 stdout 금지).
   ```
   python -c "import pdfplumber;f=r'data/<파일>.pdf';\
   open(r'data/<파일>_ext.txt','w',encoding='utf-8').write('\n'.join(('===== PAGE %d =====\n'%i)+(p.extract_text() or '') for i,p in enumerate(pdfplumber.open(f).pages,1)))"
   ```
2. `patterns.md` **전체**, 특히 **§9 상시 체크리스트** 로드.
3. **누적 대장 로드(필수)** — `spelling_correction/_검토_누적대장.md` 전체를 읽어 지금까지 확정된 수정 패턴을 근거로 삼는다. (이게 회의를 거듭할수록 검토가 촘촘해지는 핵심)
4. **해당 회의유형의 과거 검토 기록을 모두** 기준으로 삼는다:
   - VESTA → `spelling_correction/VESTA_회의_맞춤법_표현_수정표_20260615.md`, `spelling_correction/VESTA회의_20260908_맞춤법_표현_변경표.md`(103건), `handoff/2026-09-15.md`(회장님 rev 10건)
   - 그 외 회의유형은 CLAUDE.md 표의 파일 패턴으로 해당 검토표를 찾아 로드.

### 실행 모드 선택
- **기본값 = 단일 패스** — 아래 1~9 레이어를 순차 전수 적용. 대부분의 회의록은 이걸로 충분하며 토큰도 적게 든다. **명시적 요청이 없으면 항상 이 모드로 실행한다.**
- **다중 워크플로(옵션 — 사용자가 "정밀검토/다중 워크플로"라고 명시할 때만)** — `Workflow` 도구로 병렬 검토 후 어드버서리얼 QA. 토큰을 더 쓰므로 긴 회의록·중요 검토에만 사용. 구성:
  - **Phase 1 — 레이어별 병렬 검토**: 레이어 2·3(맞춤법·표기), 4(문장 호응), 5(정합성), 6(취지 보존)을 각각 별도 에이전트로 동시 실행. 각 에이전트는 `patterns.md §9` + 해당 회의유형 과거 검토표를 근거로 `{쪽, 원문, 수정안, 레이어, 사유}` 구조로 반환.
  - **Phase 2 — 통합·충돌 해소**: 레이어 간 상충(예: 표기 통일 vs 취지 보존)을 조정하고 중복 제거. **취지 보존(레이어 6)이 최상위 우선.**
  - **Phase 3 — 어드버서리얼 QA**: 통합 수정본을 별도 에이전트가 (a) 새 오타 유입 (b) 표기 회귀 (c) 체크리스트 미커버 (d) 담당지역/수치 교차 불일치 관점에서 **반증 시도**. 통과한 것만 확정.
  - 결과를 아래 8단계 산출로 병합.

### 1~6. 수정 레이어 전수 적용 (§9 순서대로)
1. **소제목** — 모든 `▶`에 구체적 제목·중복 제목 제거·단발 지시에도 제목·긴 지시 제목/본문 분리
2. **맞춤법·띄어쓰기** — 금액 단위(1만 불), 만하다, 중/여부, 별로, 여기저기, -든지, 합성동사, 되/돼, 명사구, 날짜, 성+직함 전수
3. **표기 통일** — 세일즈렙 / 리차드·폴·토마스 / RING PRO / 사전결재 / F/U→후속 관리 / 외래어 표준
4. **문장 호응** — 영어 순화, 사동 남용, 중복 제거, 장문 분리. **⚠ 회장님 비유·강도는 순화 금지**
5. **내용 정합성** — 담당자–지역 매핑·수치·인명이 문서 전체에서 교차 일치하는지 대조. **불일치·사실 확정 불가 항목은 임의 확정 말고 AskUserQuestion으로 확인**
6. **회장님 취지 보존(최상위)** — 열거 항목 누락 금지, 논지 대비 복원, 강조동사 보존, 편집 지시문 유출 금지

### 7. 자기검증 QA 패스 (반드시)
- 수정본 새 오타 재스캔 · 표기 회귀 검사 · 체크리스트 100% 커버 · **원문 대비 `diff`로 변경 전수 리뷰**

### 8. 산출 — 변경 근거표 단일 산출물 (수정본·DOCX 만들지 않음)
- **변경 근거표**(md) — 컬럼 `번호 | 쪽 | 원문 | 수정안 | 레이어 | 사유 | 상태` → `output/<파일명>_변경표.md` 로 저장하고 **화면에도 표로 띄운다.**
  - `상태` = `확정` / `확인필요`(사실 판단 미확정) 로 구분.
- **수정된 문서(수정본)나 DOCX는 만들지 않는다.** 보고서 반영은 작성자(김정민 부사장)가 직접 한다.

### 9. 누적 기록 — 다음 회의 점검 보강 (이번 지시의 핵심)
- 이번 변경표의 **`확정` 행 전부**를 `spelling_correction/_검토_누적대장.md` **맨 아래에 append** 한다. (append-only, 기존 내용 삭제·수정 금지)
  - 회의 블록 헤더: `## [회의유형] <파일명> (검토일 YYYY-MM-DD)` — 날짜는 인자/컨텍스트로 받은 값 사용.
  - 행 형식: `회의(유형·날짜) | 쪽 | 원문 | 수정안 | 레이어 | 사유 | 확정`
- **패턴 승격** — 같은 패턴이 **2개 이상 회의**에서 반복 확정되면 `patterns.md §9 상시 체크리스트`(또는 §6 오인식 표)에 규칙으로 추가하고, 누적 대장 해당 행에 `[§9 승격]` 표시.
- `확인필요` 행은 대장에 넣지 않되, 마지막 회신 요청 블록에 모아 사용자에게 확인받고, 확정되면 다음 실행 때 반영.

## 규칙
- **산출물은 변경 근거표 하나.** 수정본·DOCX는 만들지 않는다. 대신 **확정 행은 반드시 누적 대장에 append**(9단계) — 이걸 빼먹으면 검토 미완료.
- `data/` 원본 PDF·`*_rev.pdf`는 **명시 요청 없이 덮어쓰지 않는다.**
- 사실 판단(담당 지역·수치·고유명사)은 확신 없으면 **확인 질문**. 회장님 발화 취지를 임의 확정 금지.
- 마지막에 **미확인 항목(확인 필요)** 을 한 블록으로 모아 사용자에게 회신 요청.
